# Публикатор Telegram-каналов: техническое описание (сценарий n8n v3.1)

Версия на 19.10.2026. Рабочий сценарий: `n8n-backup/publish-from-github-v3.1.json` в закрытом репозитории `drokhman/channels-publisher`.

## 1. Назначение

Публикация заранее подготовленных постов в Telegram-каналы по расписанию. Источником правды служит Git-репозиторий: очередь, архив отправленных, архив ошибок. Исполнитель — n8n на отдельном VPS, публикация идёт через Telegram Bot API. Генерация контента в контур не входит.

## 2. Архитектура

```
Автор / ИИ-ассистент
   │  commit JSON в outbox/ (имя файла = время выхода)
   ▼
GitHub (private repo)  ◄──────────── GitHub REST API (Contents) ──────────┐
   outbox/  sent/  failed/  hold/  n8n-backup/  docs/                      │
                                                                           │
VPS (NL, 89.19.214.202, Ubuntu 26.04, 1 vCPU / 2 GB / 30 GB, swap 2 GB)    │
   Docker Compose, /opt/n8n                                                │
   n8n слушает 127.0.0.1:5678, снаружи открыт только SSH (22/tcp, ufw)     │
   Сценарий v3.1: cron каждые 2 мин ─── list / get / put / delete ─────────┘
        │
        └── Telegram Bot API (@MasterORservant_bot, админ каналов)
               ├── @chelovek_vs_ai
               ├── @ryadom_repetitor
               └── личка владельца (уведомления, тесты)
```

Доступ к редактору n8n: `ssh -L 5678:127.0.0.1:5678 root@89.19.214.202`, затем `http://localhost:5678`. Публичного HTTPS и вебхуков нет, все соединения только исходящие.

## 3. Структура репозитория

| Путь | Назначение |
|---|---|
| `outbox/` | Очередь. Один JSON — один пост. Содержит `.gitkeep`, чтобы каталог существовал и запрос списка не возвращал 404 |
| `sent/{id}.json` | Запись об успешной отправке |
| `failed/{file}-{YYYYMMDDTHHMM}.json` | Исходный пост целиком и описание ошибки |
| `hold/` | Посты, которые не должен видеть публикатор: тесты, заготовки, отложенные серии |
| `n8n-backup/` | Экспорты сценариев: `publish-from-github.json` (старый, выключен), v2, v3, v3.1 |
| `docs/` | Инструкция по восстановлению и установке |

## 4. Формат поста

Поддерживаются два формата.

**A. Картинка внутри файла**

```json
{
  "id": "2026-10-20-cvai-6-kardinal",
  "channel": "Человек VS ИИ",
  "chat_id": "@chelovek_vs_ai",
  "text_html": "<b>Заголовок</b>\n\nТекст",
  "image_base64": "…",
  "image_mime": "image/jpeg"
}
```

**B. Картинка по ссылке**

```json
{
  "id": "2026-10-20-1000-ryadom-s3-07-english",
  "channel": "Он рядом",
  "chat_id": "@ryadom_repetitor",
  "img": "https://iili.io/….jpg",
  "text": "<b>Заголовок</b>\n\nТекст"
}
```

- `text_html` и `text` равнозначны (сначала берётся `text_html`). Разметка — Telegram HTML.
- `id` необязателен, по умолчанию это имя файла без `.json`. Он задаёт путь `sent/{id}.json`.
- `chat_id` — `@username` канала или числовой ID чата.

## 5. Расписание: время в имени файла

Время задаётся по Москве (фиксированный UTC+3, без перехода на летнее время):

| Имя файла | Время выхода |
|---|---|
| `2026-10-20-1000-slug.json` | 20.10.2026 10:00 |
| `2026-10-20-slug.json` | 20.10.2026 в `default_hour` (10:00) |
| `slug.json` | Сразу, при ближайшем запуске |

Регулярное выражение: `^(\d{4})-(\d{2})-(\d{2})(?:-(\d{2})(\d{2}))?(?=[-_.])`. За один запуск отправляется не больше одного поста. Готовые к выходу файлы сортируются по времени выхода, затем по имени.

## 6. Узлы сценария (17)

| # | Узел | Тип | Что делает |
|---|---|---|---|
| 1 | Каждые 2 минуты | Schedule Trigger | Запуск раз в 2 минуты |
| 2 | Настройки | Code | Единственное место конфигурации (см. раздел 7) |
| 3 | Список outbox | HTTP GET `/contents/outbox` | Header Auth (GitHub); `alwaysOutputData` |
| 4 | Проверка очереди | Code | Если в `outbox/` нет JSON, один раз даёт сигнал «очередь пуста»; флаг сбрасывается, когда посты появляются |
| 5 | Сообщить: очередь пуста | Telegram sendMessage | В `admin_chat_id`; при ошибке продолжает работу |
| 6 | Выбрать пост | Code | Пауза после ошибки, время выхода, интервал по каналу, защита от повтора (`doneFiles`) |
| 7 | Скачать пост | HTTP GET (raw) | Получает JSON поста |
| 8 | Подготовить | Code | Белый список (+ `admin_chat_id` для тестов), проверка содержимого, выбор режима: `photo` / `text` / `reject`; для формата B — скрытая ссылка `<a href="img">&#8203;</a>` в начале текста и включённое превью |
| 9 | Что отправить | Switch | Фото / Только текст / Отказ |
| 10 | Отправить картинку | Telegram sendPhoto | Подпись, если текст ≤ `caption_limit`; при ошибке — ветка ошибки |
| 11 | Нужен отдельный текст? | IF | Для длинных постов формата A |
| 12 | Отправить текст | Telegram sendMessage | HTML; `disable_web_page_preview = !preview`; при ошибке — ветка ошибки |
| 13 | Итог | Code | Запись для `sent/`, обновление `lastSentAt`, `doneFiles` |
| 14 | Ошибка | Code | Запись для `failed/`, пауза (`pause_minutes`) при ошибке Telegram, текст уведомления |
| 15 | Сообщить мне | Telegram sendMessage | Уведомление об ошибке в `admin_chat_id` |
| 16 | Записать в GitHub | HTTP PUT `/contents/{path}` | Создаёт `sent/…` или `failed/…`; автор и коммиттер — `n8n-publisher (сервер)` |
| 17 | Убрать из outbox | HTTP DELETE `/contents/outbox/{name}` | По `sha` из списка; выполняется только после успешного PUT |

Порядок коммитов при успехе: `sent {id} (n8n)` → `publish {file} (n8n)`. Каждая операция сервера в журнале Git подписана `n8n-publisher (сервер) <publisher@channels-publisher.local>`.

## 7. Конфигурация (узел «Настройки»)

```js
repo: 'drokhman/channels-publisher',
allowed: ['@chelovek_vs_ai', '@ryadom_repetitor'],
admin_chat_id: '1073319162',
default_hour: 10,
min_gap_minutes: 120,
pause_minutes: 60,
caption_limit: 1000,
committer: { name: 'n8n-publisher (сервер)', email: 'publisher@channels-publisher.local' }
```

Учётные данные в n8n Credentials, в сценарии и репозитории их нет:
- **Header Auth account** — `Authorization: Bearer <GitHub fine-grained token>`, доступ только к этому репозиторию (Contents: read/write);
- **Telegram API** — токен @MasterORservant_bot.

## 8. Состояние

Хранится в `$getWorkflowStaticData('global')`, то есть в базе n8n. Сохраняется только при запусках активного сценария, при ручном запуске не сохраняется.

| Ключ | Назначение |
|---|---|
| `lastSentAt[chat]` | Время последней отправки в канал, для `min_gap_minutes` |
| `chatByFile[file]` | Канал файла, известный после скачивания; позволяет пропускать «отдыхающие» каналы без скачивания |
| `doneFiles[file] = sha` | Защита от повторной отправки, если запись или удаление в GitHub не прошли; очищается, когда файла больше нет в `outbox/` |
| `pauseUntil` | Пауза после ошибки Telegram |
| `emptyNotified` | Уведомление о пустой очереди уже отправлено |

## 9. Гарантии и обработка ошибок

- **Пост не теряется.** Файл удаляется из `outbox/` только после успешной записи в `sent/` или `failed/`.
- **Повтор исключён.** После результата Telegram пара (файл, sha) попадает в `doneFiles`, поэтому повторно этот файл не отправится, даже если GitHub не принял запись.
- **Белый список.** Пост в канал вне `allowed` получает `reject`, ложится в `failed/` и вызывает уведомление. Пауза при этом не включается.
- **Ошибка Telegram** (неверный токен, нет прав, неверная разметка): пост ложится в `failed/` с текстом ошибки и номером уже отправленного фото, если оно ушло; публикации встают на паузу на 60 минут; приходит уведомление в личку.
- **Интервал.** Не чаще одного поста в канал за `min_gap_minutes`. Накопившиеся посты выходят с этим шагом.

## 10. Проверка при вводе в эксплуатацию (19.10.2026)

| Тест | Результат |
|---|---|
| C: формат B в `admin_chat_id`, без даты | Отправлен примерно за 1 минуту; `sent/test-v31-c.json`; коммиты подписаны сервером |
| B: канал вне белого списка | `failed/test-v3-b-…json`, в Telegram ничего не ушло |
| Будущие посты (14 файлов с датами 20–24.10) | 5 минут без отправок до срока |
| Боевой пост формата B без даты | `t.me/ryadom_repetitor/177`, превью картинки под текстом |

## 11. Известные ограничения

1. **Превью над текстом недоступно.** Встроенный узел Telegram в n8n не передаёт `link_preview_options` (`show_above_text`, `prefer_large_media`), а учётные данные Telegram API нельзя использовать в HTTP Request: токен передаётся в пути URL. Варианты решения: токен в переменной окружения (`N8N_BLOCK_ENV_ACCESS_IN_NODE=false`) и HTTP-узел вместо Telegram-узла или community-узел.
2. **Нет проверки длины текста** (4 096 символов для sendMessage). Слишком длинный пост уйдёт в `failed/` с ошибкой Telegram.
3. **Конфликт `sent/{id}.json`.** Если такой файл уже есть, PUT без `sha` вернёт 422, а у узла «Записать в GitHub» нет ветки ошибки. Запуск упадёт, файл останется в `outbox/`, но повтора не будет благодаря `doneFiles`. Уведомление об этом не придёт. Нужна уникальность `id`.
4. **Картинки формата B лежат на внешнем бесплатном хостинге** (freeimage.host). Если файл удалят, превью пропадёт.
5. **Состояние в базе n8n.** При повторном импорте сценария или потере базы `doneFiles`, `lastSentAt` и пауза обнулятся.
6. **Часовой пояс фиксирован**: UTC+3 зашит в код.
7. **Публикация по одному посту за запуск.** Пропускная способность — до 30 постов в час, с учётом интервала по каналу.
8. **Резервной копии базы n8n и ключа шифрования нет.** Сценарии экспортируются в репозиторий вручную.
9. **Мониторинга работоспособности нет.** Если сервер или n8n остановятся, уведомление не придёт: об ошибке сообщает сам сценарий.

## 12. Эксплуатация

- **Добавить пост:** commit JSON в `outbox/` с нужным именем.
- **Отменить пост:** удалить файл из `outbox/` до срока.
- **Повторить после ошибки:** исправить причину, перенести файл из `failed/` в `outbox/`, убрать блок `failed`, а если фото уже ушло — убрать и `image_base64`.
- **Добавить канал:** сделать бота админом с правом публикации и дописать канал в `allowed`.
- **Откат:** выключить v3.1 и включить старый сценарий. Перед этим убрать из `outbox/` файлы с будущей датой: старый сценарий их время не учитывает. Старый сценарий хранится до 26.10.2026.
- **Ротация токена:** перевыпустить токен в @BotFather (`/revoke`) и обновить учётные данные Telegram API в n8n.
