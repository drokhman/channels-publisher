## 2. Что хранить в личном менеджере паролей

Храните именно в личном менеджере паролей, а не на рабочем компьютере:

1. Логин, пароль и двухфакторная защита аккаунта Timeweb Cloud.
2. Root-пароль сервера `n8n-de` — запасной вход через консоль Timeweb.
3. Логин и пароль владельца в n8n.
4. Токен бота @masterorservant. Его можно перевыпустить в @BotFather.
5. Логин GitHub и двухфакторная защита.
6. Пароль от SSH-ключа, если он задан.

Главное: при доступе к аккаунту Timeweb с телефона всё остальное восстанавливается.

## 3. Сценарии восстановления

### 3.1. Рабочий компьютер изъят, сломан или утерян

1. С телефона или другого компьютера войдите в Timeweb Cloud.
2. Сервер `n8n-de` → вкладка «Доступ» → удалите старый SSH-ключ `my-pc`. С этого момента старый компьютер к серверу не подключится.
3. На новом компьютере создайте ключ в PowerShell. Строка должна начинаться с `PS`, а не с `root@`:

   ```
   ssh-keygen -t ed25519 -C "n8n-channels"
   type $env:USERPROFILE\.ssh\id_ed25519.pub
   ```

4. Добавьте открытую часть ключа (строка `ssh-ed25519 ...`) на сервер. Если в панели Timeweb нельзя добавить ключ на работающий сервер, войдите через «Консоль» по root-паролю и выполните:

   ```
   mkdir -p ~/.ssh && nano ~/.ssh/authorized_keys
   ```

   Вставьте строку ключа на новой строке, сохраните (Ctrl+O, Enter) и выйдите (Ctrl+X). Учтите, что вставка в консоли браузера может не работать. Тогда сначала сбросьте root-пароль в панели, войдите по SSH с паролем из PowerShell, где вставка работает, и добавьте ключ там.

5. Если есть подозрение, что секреты с компьютера могли прочитать, перевыпустите токен бота: @BotFather → `/mybots` → @masterorservant → API Token → Revoke. Вставьте новый токен в n8n: Credentials → Telegram.
6. Проверка: `ssh root@IP_сервера` входит без пароля, тестовый пост публикуется.

### 3.2. Нет доступа к серверу вообще

1. Timeweb → сервер → «Консоль» → войти как `root` по паролю из менеджера паролей.
2. Если пароль не подходит, используйте «Доступ» → сброс root-пароля. Это перезагрузит сервер, n8n поднимется сам.
3. Набирайте пароль в английской раскладке. При вводе он не отображается — это нормально.

### 3.3. Timeweb закрыл локацию или сервер потерян

1. Создайте новый сервер в доступной зарубежной локации: Ubuntu 26.04, 2 ГБ, публичный IPv4, SSH-ключ.
2. Проверьте Telegram, Let's Encrypt и Docker Hub (раздел 4.1).
3. Выполните установку из раздела 4.2.
4. В n8n импортируйте сценарии из резервной копии в GitHub (план: еженедельная выгрузка) и заново вставьте токен бота.
5. Посты в `outbox/` на GitHub никуда не денутся: новый n8n опубликует их сам.

### 3.4. Утечка токена бота

@BotFather → `/mybots` → @masterorservant → API Token → Revoke → вставьте новый токен в n8n. Старый токен перестаёт работать сразу.

## 4. Установка с нуля

### 4.1. Проверка сети нового сервера

Для зарубежного сервера все три значения должны стабильно приходить без `000`:

```
for i in 1 2 3 4 5; do curl -m 10 -s -o /dev/null -w "TG %{http_code} %{time_total}s\n" https://api.telegram.org/; sleep 2; done
curl -m 15 -s -o /dev/null -w "LE %{http_code}\n" https://acme-v02.api.letsencrypt.org/directory
curl -m 15 -s -o /dev/null -w "GitHub %{http_code}\n" https://api.github.com
```

Если Docker Hub недоступен (так бывает на российских серверах), подключите зеркало Timeweb:

```
echo '{ "registry-mirrors": ["https://dockerhub.timeweb.cloud"] }' > /etc/docker/daemon.json && systemctl restart docker
```

### 4.2. Подготовка сервера и n8n

```
export DEBIAN_FRONTEND=noninteractive; apt update && apt -y upgrade && apt -y install docker.io docker-compose-v2 ufw && systemctl enable --now docker && fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile && echo '/swapfile none swap sw 0 0' >> /etc/fstab && ufw allow 22/tcp && ufw --force enable
```

```
mkdir -p /opt/n8n && cd /opt/n8n
cat > .env <<EOF
N8N_HOST=localhost
N8N_ENCRYPTION_KEY=$(openssl rand -hex 32)
EOF
chmod 600 .env
cat > docker-compose.yml <<'EOF'
services:
  n8n:
    image: n8nio/n8n:stable
    restart: unless-stopped
    ports:
      - "127.0.0.1:5678:5678"
    env_file: .env
    environment:
      - N8N_PROTOCOL=http
      - N8N_PORT=5678
      - N8N_SECURE_COOKIE=false
      - GENERIC_TIMEZONE=Europe/Moscow
      - TZ=Europe/Moscow
      - N8N_DIAGNOSTICS_ENABLED=false
      - N8N_RUNNERS_ENABLED=true
      - NODE_OPTIONS=--max-old-space-size=768
    mem_limit: 1200m
    volumes:
      - n8n_data:/home/node/.n8n
volumes:
  n8n_data:
EOF
docker compose pull && docker compose up -d && sleep 30 && docker compose ps
```

Важно: ключ `N8N_ENCRYPTION_KEY` из файла `/opt/n8n/.env` шифрует все сохранённые в n8n токены. Если переносите n8n со старого сервера вместе с данными, перенесите и этот файл. Если ставите с нуля, токены всё равно вводятся заново.

### 4.3. Вход в редактор n8n

n8n не виден из интернета, в него заходят через SSH-туннель с компьютера:

```
ssh -L 5678:127.0.0.1:5678 root@IP_сервера
```

Пока окно открыто, редактор доступен в браузере по адресу http://localhost:5678.

## 5. Схема публикации (план)

1. Утром Perplexity присылает 2–3 темы. Владелец выбирает одну.
2. Perplexity пишет текст и делает картинку, владелец согласовывает.
3. По команде «публикуй» Perplexity кладёт пост в `outbox/` закрытого репозитория GitHub.
4. Раз в 2 минуты n8n проверяет `outbox/`, публикует картинку и текст через @masterorservant и переносит пост в `sent/` со ссылкой на сообщение.
5. При ошибке бот пишет владельцу в личку.
