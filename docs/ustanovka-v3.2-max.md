# Ветка MAX: сценарий v3.2 (около 1,5–2 часов)

> Заменено 01.11.2026: MAX публикуется с российского сервера, см. `docs/ustanovka-max-ru.md`. Ветку v3.2 не включать, иначе посты уйдут в MAX дважды.

v3.2 — это v3.1 плюс ветка MAX после успешной отправки в Telegram. Telegram-часть не изменена (кроме подписи `workflow: 'v3.2'` в архиве).

Что делает ветка:
- после записи в `sent/` и удаления из `outbox/` берёт тот же пост и публикует в канал MAX;
- `image_base64` загружает в MAX (`POST /uploads` → файл → токен), `img` прикладывает картинкой по ссылке; в MAX картинка стоит над текстом;
- переводит HTML Telegram в HTML MAX: `b i u s code pre a blockquote mark` сохраняются, остальные теги (`tg-spoiler`, `tg-emoji`, `span`) снимаются, текст внутри остаётся;
- повторяет отправку один раз через 10 секунд только при `attachment.not.ready` — в этом случае поста точно нет. Любая другая ошибка без повтора, чтобы не было дубля;
- успех → `sent-max/{id}.json` (mid, ссылка MAX, ссылка Telegram); ошибка → `failed-max/{id}-{время}.json` с полным постом и сообщение вам в личку;
- ошибка MAX не ставит паузу Telegram и не возвращает пост в очередь;
- `"max": false` в файле поста — не дублировать; `"max_text_html"` — свой текст для MAX;
- пока в «Настройках» `max.enabled: false` или у канала пустой `chat_id`, сценарий работает ровно как v3.1.

Где выполнять: **Сервер** — в SSH-сессии на `89.19.214.202`; **Компьютер** — у вас; **n8n** — в редакторе через туннель; **MAX** — в приложении MAX.

## Шаг 0. До начала

Нужны: верифицированный профиль на платформе MAX для партнёров, созданный бот и его токен. Бот добавлен администратором в канал(ы) MAX с правом писать посты.

## Шаг 1. Сертификат Минцифры и доступ к API (20–30 минут)

1. **Компьютер.** `ssh root@89.19.214.202`.
2. **Сервер.** Скачайте корневой сертификат и сверьте отпечаток:
   ```sh
   mkdir -p /opt/n8n/certs && cd /opt/n8n/certs
   curl -fsSL -o russian_trusted_root_ca.pem https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt
   openssl x509 -in russian_trusted_root_ca.pem -noout -fingerprint -sha256
   ```
   Проверка: `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`. Если отличается — остановитесь.
3. **Сервер.** Проверьте доступ к API MAX из Нидерландов (вместо `ТОКЕН` — токен бота):
   ```sh
   curl -s -w "\nHTTP %{http_code}\n" --cacert /opt/n8n/certs/russian_trusted_root_ca.pem \
     -H "Authorization: ТОКЕН" https://platform-api2.max.ru/me
   ```
   Проверка: `HTTP 200` и JSON с именем бота. Если `502`, `403` или тайм-аут — API не пускает сервер из-за рубежа; дальше не идём, нужен посредник в РФ (отдельная задача). Из тестовой среды ассистента в США API ответил `502`.
4. **Сервер.** Узнайте `chat_id` каналов:
   ```sh
   curl -s --cacert /opt/n8n/certs/russian_trusted_root_ca.pem -H "Authorization: ТОКЕН" \
     https://platform-api2.max.ru/chats | python3 -m json.tool | grep -E '"(chat_id|type|title)"'
   ```
   Проверка: у вашего канала `type: "channel"` и числовой `chat_id` (обычно отрицательный). Запишите его.
5. **Сервер.** Подключите сертификат к n8n: в `/opt/n8n/docker-compose.yml` у сервиса n8n добавьте
   ```yaml
       environment:
         - NODE_EXTRA_CA_CERTS=/certs/russian_trusted_root_ca.pem
       volumes:
         - /opt/n8n/certs:/certs:ro
   ```
   (в существующие списки `environment` и `volumes`, не дублируя ключи). Затем `cd /opt/n8n && docker compose up -d`.
   Проверка: `docker compose exec n8n node -e "fetch('https://platform-api2.max.ru/me',{headers:{Authorization:'ТОКЕН'}}).then(r=>console.log(r.status))"` выводит `200`.

Не отключайте проверку сертификатов (`NODE_TLS_REJECT_UNAUTHORIZED=0`) — это снимает защиту для всех адресов, включая GitHub и Telegram.

## Шаг 2. Импорт v3.2 (20–30 минут)

1. **Компьютер.** `ssh -L 5678:127.0.0.1:5678 root@89.19.214.202`, затем `http://localhost:5678`.
2. **n8n.** Credentials → Create → Header Auth. Name: `MAX bot`; Header Name: `Authorization`; Value: токен бота. Save.
3. **Компьютер.** Скачайте `n8n-backup/publish-from-github-v3.2.json`.
4. **n8n.** Create workflow → «…» → Import from File.
   Проверка: 38 узлов, название «Публикация из GitHub в Telegram и MAX v3.2».
5. **n8n.** Ключ GitHub — в «Список outbox», «Скачать пост», «Записать в GitHub», «Убрать из outbox», «MAX: записать в GitHub». Ключ Telegram — в «Отправить картинку», «Отправить текст», «Сообщить мне», «Сообщить: очередь пуста», «MAX: сообщить мне». Ключ `MAX bot` — в «MAX: адрес загрузки», «MAX: загрузить файл», «MAX: отправить», «MAX: отправить повторно».
   Проверка: красных значков нет.
6. **n8n.** Узел «Настройки»: в блоке `max` поставьте `enabled: true` и `chat_id` канала MAX напротив **одного** канала Telegram, например `'@chelovek_vs_ai': '-71234567890'`. Второй оставьте пустым.
7. **n8n.** Save. Выключите v3.1 (Active → off), включите v3.2.
   Проверка: активен только один сценарий публикации — иначе посты уйдут дважды.

## Шаг 3. Проверка (15–20 минут)

1. Дождитесь ближайшего поста этого канала (или попросите ассистента положить тест в `outbox/`).
2. Проверка: пост в Telegram как обычно; в MAX тот же пост с картинкой сверху; в GitHub появились `sent/{id}.json` и `sent-max/{id}.json`.
3. Сверьте в MAX: жирный, ссылки, переносы строк. Если переносы склеились — сообщите ассистенту, это правится в узле «MAX: подготовить».
4. После 2–3 удачных постов добавьте `chat_id` второго канала.

## Откат

Выключите v3.2, включите v3.1. Либо в «Настройках» v3.2 поставьте `max.enabled: false` — Telegram продолжит работать как раньше.

## Что не сделано

- Повторной отправки из `failed-max/` нет: такой пост публикуется в MAX вручную.
- Сохранение ID поста MAX нужно для будущих правок; сам механизм правок в MAX не реализован.
- Проверка сделана на n8n 2.45.7 с имитацией API MAX; живой API MAX ещё не проверялся.
